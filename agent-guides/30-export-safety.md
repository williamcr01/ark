# Export safety

Decks are exported to PDF and PowerPoint. PDF is printed from the deck itself and
is always faithful. PowerPoint is different: it rebuilds the slide out of native
shapes so the recipient can move and edit them, and its shape model is narrower
than CSS.

Stay inside the subset below and a deck exports as real, editable PowerPoint
content. Step outside it and that part of the slide still appears, but flattened
to a picture the recipient cannot edit.

## Fonts

PowerPoint stores **one** font name per run of text — there is no fallback list —
and it resolves that name against the fonts on the recipient's machine.

- Choose from the approved font ids in the system prompt. Declare them once:

  ```html
  <html lang="en" data-ark-font-display="cambria" data-ark-font-body="calibri"></html>
  ```

  ```css
  :root {
    --ark-font-display: 'Cambria', 'Caladea', serif;
    --ark-font-body: 'Calibri', 'Carlito', sans-serif;
  }
  ```

- Reference only the variables: `font-family: var(--ark-font-body);`. Never write
  a literal family name on an element, and never invent a stack.
- The second family in each stack is a metric-compatible clone. It exists so a
  deck renders with the same line breaks on machines that lack the Office font.
  Keep both entries and keep the order.
- Weights 400 and 700 survive the export. Others collapse to the nearer of the
  two, so never rely on 300 or 600 to carry a distinction that matters.

## Text

- Keep text in real elements. Text baked into an inline SVG, drawn on a canvas,
  or injected at runtime cannot become editable PowerPoint text.
- One block element per block of text. A heading and its paragraph are two
  elements, not one element with a `<br>` between them.
- Use `<ul>`/`<ol>` for lists so they export as real PowerPoint bullets.
- `text-transform` and `letter-spacing` carry over; `text-shadow` and
  gradient-clipped text do not.

## Shapes and layout

- Solid fills, linear gradients, borders, border-radius, and box-shadow all map
  to native PowerPoint shapes.
- These have no PowerPoint equivalent and flatten the element that uses them:
  `backdrop-filter`, `filter`, `mix-blend-mode`, `clip-path`, `mask`,
  `conic-gradient`, and content generated by `::before` / `::after`.
- Use them deliberately on decorative elements, never on a slide's main
  container, and never to render text or data the recipient may want to edit.
- Lay out with flex and grid as normal. Export measures the rendered result, so
  the mechanism does not matter — only the final geometry does.

## Images and charts

- `<img>` with a `data:` URI or an `ark-asset:` id exports as a real picture.
- Inline SVG exports as a picture. Keep any label a reader may want to change in
  HTML next to the SVG rather than inside it.
- Chart.js canvases export as pictures today. Keep chart titles, axis labels, and
  callouts in HTML around the canvas so they stay editable.
